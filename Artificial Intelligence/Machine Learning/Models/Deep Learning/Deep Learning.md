# Deep Learning

Not a single model but a **framework**: models built out of **multiple layers of non-linear processing units**, where each layer learns a representation of the layer below, forming a hierarchy from low-level to high-level features.

By contrast, a **shallow** model is a network with few layers (say less than 3).

It includes:

- deep MLP (an MLP with many layers),
- [[CNN]] - the deep model for images,
- [[RNN]] and recursive NN - deep along time / along the structure,
- generative and energy-based models,
- and the randomized versions, see [[Randomized Neural Networks]].

The common ingredients:

1. many layers of non-linear units;
2. supervised **or** unsupervised learning of the representation in each layer;
3. hence a hierarchical, sparse/distributed representation of the input $\to$ [[Representation Learning]], [[Distributed Representation]].

> [!note] Where the idea comes from
> It is already in the XOR example of [[Neural Networks]]: the hidden layer re-represents the input so that the task becomes easy for the output layer. Deep learning simply repeats that step many times.

## Do we need many layers?

[[Universal Approximation]] says one hidden layer is enough *in principle*, but says nothing about **how many units**. The interesting results are about **efficiency**, not expressivity.

### The logic-circuit example: parity

Odd parity: return 1 iff there is an odd number of $1$s among $N$ binary inputs. It is XOR extended to $N$ variables.

- **Two layers** (disjunctive normal form, AND gates then one OR): you need one AND per positive configuration, so $2^{N-1}+1$ gates - **exponential**.
  - 3 inputs $\to$ 5 gates, 4 inputs $\to$ 9 gates, 8 inputs $\to$ 129 gates.
- **$\log N$ layers**: a complete binary tree of XOR nodes, $N-1$ internal nodes, 3 gates each $\to$ $3(N-1)$ gates - **polynomial**.
  - 8 inputs $\to$ 21 gates instead of 129.

The same phenomenon shows up in NN.

### No-flattening

> [!important] No-flattening results
> There are families of functions that can be approximated efficiently by an architecture of depth $>d$, but need a **much larger** (up to exponentially larger) model if the depth is limited to $\le d$.

Two related statements:

1. A one-hidden-layer network may need an exponential number of units (in the worst case, roughly one hidden unit per input configuration to be distinguished).
2. More layers help - for the number of units/weights, and/or for the **learnability** (how fast good parameters can be found).

Which classes of functions actually benefit is still an open question: a complete list of no-flattening theorems would say exactly when deep beats shallow.

### Why: compositionality

Simple concepts represented in one layer are reused as **primitives** by the next layer to build more complex ones, so the model avoids representing (and learning) all the combinations explicitly.

You learn each word / sub-pattern, not every possible combination of them - and you can reuse it in different contexts.

> [!important] Less is better
> Do not read "deep" as "huge". A deep network is a **compact** model with respect to the shallow one that would solve the same task (potentially exponentially more compact). Fewer units and fewer weights $\to$ easier learning, good generalization with **fewer examples**.

## The inductive bias of depth

Choosing a deep model encodes a very general belief: *the function to learn is a composition of simpler functions*, i.e. nested factors of variation.

- If the task matches this bias, the deep shape is suitable - and generalization tends to be better than a shallow model with the **same** number of units/weights.
- Typical matching domains: images (composition of sub-parts), language (text and speech), music, multi-scale phenomena in space and time.
- It is still a bias, but a much more general one than hand-made constraints (an ad hoc $\phi$ in [[Linear Basis Expansion]], engineered features).

> [!warning]
> Nothing is magic without assumptions. Depth is a bias like any other, so [[No Free Lunch]] applies: there is no guarantee your task has that property.

### Beating the curse of dimensionality

Many learners rely on **local** approximation ([[k-NN]], local kernels, decision trees): to distinguish $O(k)$ regions of the input space they need $O(k)$ examples, and in high dimension the space is huge $\to$ [[Curse of Dimensionality]].

Assuming instead that the data are generated by a **composition of factors** at multiple levels lets the model distinguish an exponential number of regions with $O(k)$ examples, i.e. **generalize non-locally**. Same argument as in [[Distributed Representation]], one level up.

### Smoothness through structure

For a given number of parameters, deeper networks impose **more smoothness** than shallow ones: each layer works on the already smooth surface produced by the previous one. An implicit constraint, as opposed to the explicit ones of classical models.

## Practical issues

- **How many layers? How many units?** No general answer $\to$ [[Model Selection and Assessment]].
- With very large networks the number of hyperparameters explodes, so many architectural choices are fixed by experience instead of by search - running [[Cross Validation]] over everything would be far too expensive. See [[Hyperparameter Guidelines]].
- Deeper $\to$ fewer units per layer $\to$ fewer parameters $\to$ less training data needed. **But** many layers are harder to optimize.

That last point is what the techniques below are about.

### Why the hardware matters

Almost all the computation in a deep network is **matrix multiplication** - dot products that are independent of each other, so they parallelize almost perfectly. That is the whole reason GPUs, and later the dedicated tensor/neural processing units, made deep models practical: the algorithm did not need to change, the same arithmetic just got much cheaper.

## The gradient problem

What happens to the magnitude of the gradient as we backpropagate through many layers? With $\boldsymbol{h}^{(l)}=F_l(\boldsymbol{h}^{(l-1)})$ and $F=F_M\circ\dots\circ F_1$:

$$
\frac{\partial F}{\partial w_l}=\frac{\partial F_M}{\partial \boldsymbol{h}^{M-1}}\cdot\ \dots\ \cdot\frac{\partial F_l}{\partial w_l},
\qquad
\left\lVert\frac{\partial F}{\partial w_l}\right\rVert\approx\rho^{\,M-l+1}
\ \text{ if }\ \left\lVert\frac{\partial F_i}{\partial \boldsymbol{h}^{i}}\right\rVert\approx\rho .
$$

$$
\rho<1 \Rightarrow \text{vanishing},\qquad \rho>1 \Rightarrow \text{exploding}.
$$

Concretely with sigmoid/tanh: $f'<1$ always, so in a $d$-layer network the $\delta$ of the **front** layers (close to the input) is a product of $d$ small numbers and decreases exponentially with $d$ - those layers train very slowly. Exploding is rarer with squashing functions, and typical of [[RNN]] instead.

### Gradient clipping

Repeated multiplication through layers creates **cliffs** in the error surface: a high-derivative point catapults $\boldsymbol{w}$ very far. Clipping bounds the step while keeping the direction:

$$
\text{if } \lVert \boldsymbol{g}\rVert>v \ \text{ then }\ \boldsymbol{g}\leftarrow v\,\frac{\boldsymbol{g}}{\lVert \boldsymbol{g}\rVert}
$$

with $\boldsymbol{g}$ the gradient and $v$ a norm threshold.

### ReLU

$$
f(x)=\max(0,x)=\begin{cases}0 & x\le0\\ x & x>0\end{cases}
$$

Why it is the default for deep models:

- **Better gradient propagation:** $f'(x)=1$ for positive $net$, so no shrinking factor per layer - unlike sigmoids, whose $f'$ is always $<1$ and goes to $0$ in saturation.
- **Sparse activation:** in a randomly initialized network only about 50% of the units are active (non-zero output).
- **Cheap:** only comparison, addition and multiplication.
- Faster and more effective training of deep architectures.

> [!warning] Not differentiable in 0
> Libraries simply take $f'(0)=0$ (left derivative) or $1$ (right derivative). The approximation is safe: numerical precision makes an exact $net=0$ unlikely. The principled route is non-differentiable optimization for piecewise-linear functions.

**Trick:** initialize the biases to a small positive value (e.g. $0.1$) so most units start active and let the derivative pass.

**Variants** (they mostly recover the left part, so units are not switched off and the mean activation is closer to zero, while keeping the linear part that makes optimization easy):

- **Leaky ReLU** - a small slope for $x<0$.
- **ELU** (exponential linear unit) - exponential on the left.
- Many others perform comparably.

### Pre-training

An older route to deep training, now mostly replaced by end-to-end backprop: see [[Representation Learning]].

### Adversarial learning

Two networks trained against each other: one **generates** candidates, the other **evaluates** them, and each gets better because the other does.

- **Adversarial training** - feeding a model deliberately perturbed inputs to make it robust to them; it also acts as a regularizer.
- **GAN** (generative adversarial network) - the generator/discriminator pair used as a *generative* model; this is where photorealistic images of people who do not exist come from.

## Open puzzles

Why very large networks behave the way they do - all of these are open research lines, not settled results.

### The non-overfitting puzzle

Huge over-parametrized networks show an **apparent lack of overfitting**, despite having the capacity to reach zero training error on **randomly labelled** data - which proves the capacity is really there.

Part of the explanation: gradient descent applies an **implicit regularization**.

- The SGD variants that normalize (batch normalization, weight normalization) perform a minimization equivalent to **maximizing the normalized margin**.
- Even plain gradient descent, with no explicit normalization or penalty, converges towards the **maximum $L_2$ margin** solution - it implicitly controls complexity through a unit $L_2$ norm constraint.

So the complexity control is there; it is just not written in the loss. Compare [[SVM]], where maximizing the margin is the *explicit* objective.

### Double descent

Increase the model size (or the training time) and the test error does **three** things: it improves, then gets worse - the classical U-shape of [[Overfitting]] - and then improves **again**, often past the first minimum.

$$
\text{underfit}\ \longrightarrow\ \underbrace{\text{classical U-shape}}_{\text{bias}\,\downarrow,\ \text{variance}\,\uparrow}\ \longrightarrow\ \underbrace{\text{interpolation threshold}}_{\text{peak: just big enough for }R_{emp}=0}\ \longrightarrow\ \text{second descent}
$$

- The peak sits at the **interpolation threshold** - the capacity at which the model is just able to drive the training error to zero.
- It happens along **two different axes**: growing the number of parameters, *or* simply training longer.
- Seen in CNNs, ResNets and transformers with millions of parameters.
- **Label noise makes it visible** (the classic demonstration uses ~15% corrupted labels); careful [[Regularization]] often hides it entirely.

A small example that already shows it: polynomial regression with a penalty. Past the degree that achieves zero training error, the fit is driven **only by the penalty term**, and the polynomial becomes more and more piecewise-linear rather than wilder. Take the median error over many runs and the double-descent curve appears.

> [!warning] It does not refute the trade-off
> The U-shape of [[Statistical Learning Theory]] and [[Bias-Variance Tradeoff]] is a statement about *capacity*, and the number of parameters is **not** capacity - see [[VC Dimension]]. The attempts to explain double descent re-read it exactly this way: through an "effective model complexity" relative to the number of data, or by reinterpreting the classical bounds. Nobody fully understands it yet.

### Grokking

Generalization arrives **long after** the model has overfitted the training data.

Here the architecture is **fixed** and the axis is the **number of training steps**: the network reaches the interpolation threshold, sits there apparently overfitted for many epochs, and then - with no change to the model - the test error falls.

> [!important] Double descent vs grokking
> Same surprise, different axis. Get this pair straight and both become easy to state.
>
> | | what moves | what stays fixed | when generalization appears |
> |---|---|---|---|
> | **Double descent** | model size, *or* training time | - | after passing the interpolation threshold in **capacity** |
> | **Grokking** | training steps only | the architecture | many epochs after $R_{emp}$ already hit zero |

First observed on small algorithmic datasets, later found beyond those - and beyond neural networks altogether, which suggests it is a property of the optimization, not of the architecture.

### Redundancy and the lottery ticket

- **Redundancy:** given a few weight values per feature, the rest can be predicted - in the best case more than 95% of the weights, with no accuracy drop. Networks can be compressed by pruning and quantization without losing accuracy.
- **Lottery ticket hypothesis:** then why train large networks at all? Because good performance depends on the lucky initialization of one or more **subnetworks**, and a large network contains exponentially more of them. It is testable: retraining the pruned network **from the same initialization** should perform as well as the full one.
- **Randomization** of the weights, both as initialization and as a permanent choice $\to$ [[Randomized Neural Networks]].

## Where it is used

NLP (speech recognition, machine translation, sentiment analysis, question answering), computer vision (object recognition, segmentation, synthesis, medical imaging), game playing. The pattern is the same everywhere: **compositionality of the features** is what makes the domain suitable.
